# 钓鱼站停产商品每日限时购买

Status: done

## Problem Statement

钓鱼站停产钓具需要按游戏时间每天开放购买，同时保留原有“停产”分类。开放时显示价格，关闭时显示“在库房里没有”；跨越关闭时间后，旧页面的购买请求也必须被拒绝。

## Solution

192 件停产鱼竿、渔轮和拟饵每天在游戏时间 09:00–12:00、20:00–22:00 开放购买，结束时间不包含在窗口内。沿用现有游戏时钟、各店货架和实际价格。

## User Stories

1. 玩家可以始终通过“停产”分类浏览旧款钓具。
2. 开放时段内可以看到价格并正常购买；其他商品不受影响。
3. 关闭时显示缺货，旧价格的购买请求返回原生缺货结果，不扣款。
4. 商店现有库存变更轮询在跨过开放或关闭边界后触发重新加载。

## Implementation Decisions

- 停产清单取自现有 type 2 商品目录，并限于钓具品类；食品、饮料、套盒不在本次范围。
- 将清单内目录状态从 1 改为专用标记 128，并同步配置 SHA1。其余目录记录保持不变，静态数据库保持只读。
- 服务端货架查询与购买校验共用游戏时间窗口；仅作用于钓鱼站。成交价格仍由服务端有效货架决定，扣费与入库继续沿用现有事务和幂等链路。
- 客户端基线为 4.0.25034。该版本将停产分类与禁止购买绑定，需配套本地兼容补丁，才能保留分类并按实际库存显示价格。
- `tools/discontinued-shop-compat.py` 校验原版客户端完整 SHA256，只生成新的补丁文件，不修改安装目录。补丁保留停产分类识别，允许有库存的限时商品显示价格，零价格时使用原生缺货提示。
- 22/6 的原生布尔响应根据店铺及上次加载的 FILETIME 判断是否跨越时间边界；房产商店沿用已有行为。关闭时的购买请求使用原生操作结果 129，避免通用内部错误。

## Usage

按项目既有构建流程编译并部署 gameserver。配置与清单通过 Go embed 编入程序，不是复制到安装目录即可生效的独立运行文件。

客户端须先正常退出，并自行备份原版 `GameAssembly.dll`。在该文件所在目录，使用 Python 运行仓库中的补丁工具，参数依次为 `GameAssembly.dll` 和一个不存在的输出文件名，例如 `GameAssembly.timed-shop.dll`。工具成功后，用输出文件替换原文件；保留备份用于恢复。其他版本或已修改文件会因哈希不匹配而被拒绝。仓库不包含客户端 DLL 或服务端构建产物。

服务端目录状态与客户端补丁应配套使用。恢复原版客户端时，应同时恢复原版服务端配置，避免分类与价格显示不一致。

## Testing Decisions

- 覆盖 08:59、09:00、11:59、12:00、19:59、20:00、21:59、22:00 的游戏时间边界。
- 使用隔离玩家数据库验证开放时成交、扣费、发货；关闭时原生缺货且不扣费。
- 覆盖货架过滤、普通商品、其他商店、未知店铺、银币/金币价格和跨整日库存变更查询。
- Python 检查完整目录，验证仅 192 条状态变化、其他解压字节不变，以及配置长度和 SHA1 一致。

## Out of Scope

不修改静态数据库、世界时钟、非钓具停产状态、购买事务或幂等机制。不分发客户端文件、玩家数据及本机安装文件。
